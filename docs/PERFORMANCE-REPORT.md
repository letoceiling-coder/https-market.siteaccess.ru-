# Производительность — Phase 7

## Условия

- Production: `npm run build` + `npx next start -p 3100`.
- Хост: Windows 10, локальный Node.
- Замеры TTFB: `Invoke-WebRequest` (полный HTML-документ).
- Замеры SPA: Cursor browser, `performance.now()` + MutationObserver, флаг `reloaded`.
- Leaflet: CDP `Runtime.evaluate` после 1,2 с на `/map`.

## Сборка

`npx tsc --noEmit` — 0. `npx eslint src` — 0. `npm run build` — 0. Маршрут `/map` в билде помечен `◐` (Partial Prerender).

## Карта

| Метрика | Значение |
|---|---|
| Контейнеров Leaflet | 1 (после фикса двойного инстанса) |
| Desktop size (CDP 1440) | 918×718, 16 тайлов |
| Mobile size (CDP ~390) | 370×578, 8 тайлов, все загружены |
| Маркеров | 70 DEMO-пинов |
| SDK | `next/dynamic` + `ssr: false` — Leaflet не попадает в бандл главной |

Первый холодный `/map` на проде ответил HTTP 200 за ~8 с вместе со стартом сервера; повторные запросы — быстрее (страница уже в памяти).

## Ограничения

- Тайлы OSM с публичного CDN: на медленной сети LCP карты зависит от внешних серверов.
- 70 маркеров без кластеризации: приемлемо для DEMO, на тысячах точек нужна кластеризация.
- Dev (`next dev`) на холодном старте компилирует маршруты десятки секунд — это не показатель продакшена.
